# Decisions

Non-obvious calls, one line each, newest last.

- 2026-11-05 · Made from the kit template at v0.2.2 (the newest kit tag) with the Android app; the template's desktop app is left out, since the goal asks for the web and Android only.
- 2026-11-05 · Releases start at 0.0.1 (`first-version` in release.yml) so every merge ships a normal release before the goal's v0.1.0; the PR that gets a requested audiobook and ebook verified and filed end to end adds `docs/releases/0.1.0.md`, which makes that merge v0.1.0.
- 2026-11-05 · License GPL-3.0-only for Folio's own code (the kit stays MIT, which GPL allows); the original projects are credited in the README.
- 2026-11-05 · The first commit (goals and README) went to main directly, since a pull request needs a branch to merge into and the repository was empty.
- 2026-11-05 · Merged branches are deleted by the kit's cleanup-branches workflow (copied in), as the kit does, because this environment's proxy refuses ref deletes.
- 2026-11-05 · Works and editions: editions of one work are joined by Open Library's work key, else by the title before its subtitle (no leading article) and the first author's letters (`text::title_key`, `text::person_key`); Audnexus has no work key, so audiobooks join by title and author.
- 2026-11-05 · Each edition keeps the sources' whole answer as JSON (`editions.meta`) with the searched columns beside it, so new fields need no table change.
- 2026-11-05 · Ebook sources are merged in the order Open Library, Hardcover, Google Books (first non-empty field wins); the blurb takes the longest. Hardcover is asked only with a token; one failing source doesn't stop the others.
- 2026-11-05 · The metadata tests serve hand-written fixtures in each source's shape from a local server: this build environment can't reach Audnexus, Open Library or Hardcover.
- 2026-11-05 · Adding and removing editions is for admins until users and requests (goal 6) come; reading is for anyone signed in.
- 2026-11-05 · Wanting is per exact edition, under one preferences profile per format (made at the start, edited on the Wanted page); searching, verifying and importing read the same profile.
- 2026-11-05 · Followed authors' and series' audiobooks come from Audible's public catalogue (`api.audible.<store>/1.0/catalog`), since Audnexus has no author or series book lists; each ASIN is then read from Audnexus. Ebooks come from Open Library's author works and work editions (Open Library's own ebook editions first).
- 2026-11-05 · Every offer from a followed author or series is looked at once (`follow_seen`), so a book taken off the wanted list is not added back; an offer whose source couldn't be reached is asked again next time.
- 2026-11-05 · A language the source doesn't state is let through when wanting; the arriving files are checked for it.
- 2026-11-05 · Lantern search goes through its Prowlarr API (`GET /api/v1/search`, there today); grabs, progress and callbacks go through its download hub (`/api/hub/*`, Lantern's goal 9, not built yet), as written down in `docs/LANTERN.md`. Folio asks about grabs every minute, so callbacks are a speed-up, not a need.
- 2026-11-05 · A result is grabbed automatically only at 70 points or more (a setting) and never when refused; a person may grab a refused result, after a danger confirm, and it is still verified on arrival.
- 2026-11-05 · Lantern's callback address carries a random secret (kept in `folio_kv`) instead of an API key, since Lantern only knows Folio's address.
- 2026-11-05 · Folio is built in parallel tracks (core pipeline, player and reader, Android, compatibility, migration); `docs/TRACKS.md` pins who owns which files and the schema and playback API they share. Lengths are milliseconds everywhere (Audnexus gives chapters in ms), and progress is last-writer-wins by `updated_at`.
- 2026-11-05 · The library folder (`library_dir`, default `/library`) is the one place outside the data folder Folio writes to: books are filed there with hardlinks from Lantern's download folder, so both must be on the same disk.
- 2026-11-05 · `docs/GOALS.md` missed the first commit (a failed download stopped the command before it was written); it is added with TRACKS, word for word as saved then.
- 2026-11-05 · Library files are sent with `Content-Encoding: identity`, so the server's gzip layer leaves them alone: audio and EPUB are compressed already, and a gzipped answer would drop Range (jumping in a long book).
- 2026-11-05 · Migration reads each source's database file directly, copied with its `-wal` into a scratch folder first, so the source app can keep running and is never written to (SQLite writes beside a file even when opened read-only); no API keys are needed.
- 2026-11-05 · Migration reads Readarr, LazyLibrarian and Listenarr for their wanted lists only; books already had come from Audiobookshelf or Calibre, where the files are. Calibre-Web's progress points at `calibre:<id>`, the ids the Calibre reader gives.
- 2026-11-05 · A Readarr book is an audiobook when its edition's format says audio, or its author's quality profile allows only audio qualities; otherwise an ebook.
- 2026-11-05 · The web reader opens EPUBs in the browser (zip and roxmltree in WebAssembly), not on the server: one file to fetch, and the same file serves offline reading. Chapters show in a frame with `allow-scripts` only so the reader's own listeners work; the book's scripts, frames and inline handlers are removed and a Content-Security-Policy with `script-src 'none'` and only `blob:`/`data:` loads guards the rest.
- 2026-11-05 · The player and reader save a place with the time it was made; a place the server can't take waits in `localStorage` and goes when the browser is back online, and the server keeps the newest, so offline listening never overwrites newer progress from another device.
- 2026-11-05 · Verification counts a fact the files don't give (no narrator tag, no ISBN in the OPF) as half a match, never a match: Folio doesn't guess, so an untagged download waits under Review unless the rest is conclusive. 85% is the default bar; a hard failure (runtime off by more than 3%, a sample, DRM, another language, not an EPUB) always goes to Review, never straight to the bin.
- 2026-11-05 · Only EPUB can be checked against its own metadata; AZW3 and PDF downloads always wait under Review.
- 2026-11-05 · ffmpeg and ffprobe come from the static builds in `mwader/static-ffmpeg` (copied into the distroless image), and CI installs Ubuntu's ffmpeg through the kit's new `apt-packages` input, so the tests run real files.
- 2026-11-05 · Every outside protocol (OPDS, KOReader, Audiobookshelf, Kobo) reads the library through one view, `compat::shelf` (an edition with files in `edition_files` is a book), so per-user libraries later are one filter there. OPDS signs in with HTTP Basic (what e-readers support); a right username and password is remembered for 10 minutes so each page doesn't wait for bcrypt, and 10 wrong tries per username in 5 minutes are refused.
- 2026-11-05 · Migration matches audiobooks only by ASIN and ebooks only by ISBN (the goal's never guess); a book without one is listed for a person with the reason. A dry run looks nothing up, so it says "would be added" rather than checking the sources.
- 2026-11-05 · Migrated places without a time count as old (1970), so they never replace a place made in Folio; source people go to the Folio account with the same user name in any case, or as the run's `users` map says.
- 2026-11-05 · Migrated books' files are kept in `migration_files` (waiting) and handed to core's import (`import::queue_local`) once it lands, so they are verified and filed like any download; the source files are never moved.
- 2026-11-05 · Android plays audiobooks with Media3 (ExoPlayer in a MediaSessionService), streaming through the app's own OkHttp client so the bearer token goes along; the place is one position across all of a book's files, as docs/TRACKS.md has it.
- 2026-11-05 · Android keeps places and bookmarks in the kit's offline outbox (only the latest place per book waits) and sends them in order; the server's last-writer-wins answer comes back into the phone's copy, so opening a book takes the newer of the two.
- 2026-11-05 · Android reads EPUBs with its own WebView reader (CSS columns, one spine item at a time) instead of a reader library: no Fragment host is needed in the Compose app, and the locator is exactly docs/TRACKS.md's {href, progression, total_progression}, with total progression weighed by the spine items' sizes. Pages are served from the EPUB file under a content security policy that lets only the reader's own script run.
- 2026-11-05 · Android downloads run in the app's process, one book at a time, into files/downloads/<edition>/ with the server's answers beside them so the pages open offline; one stopped by the app closing goes on at the next start. WorkManager was left out: a book is fetched while someone is looking at the app.
- 2026-11-05 · With clean-up on, the library gets new files (a tagged M4B, a rewritten EPUB) and Lantern's download stays as it is for seeding; hardlinks are used when clean-up is off, since a hardlinked file can't be changed without changing the seed. A lone M4B keeps its audio as is (`-c:a copy`); MP3s are encoded to 64 kb/s AAC.
- 2026-11-05 · A download that can't be filed stays checked with the reason and waits for File again, instead of failing again every minute.
- 2026-11-05 · KOReader sends only an MD5 of a password, which bcrypt can't be checked against, so each account sets a separate KOReader sync password (kept as SHA-256 of that MD5); KOReader's Register is refused with where to set it. Books are matched by KOReader's sampled MD5 or file-name MD5, worked out once per file; a place from another app goes to KOReader as the start of its spine item (`/body/DocFragment[n]/body`), since a CFI can't be turned into an XPointer without laying the book out.
- 2026-11-05 · The Audiobookshelf API answers as server 2.25.1 (the last with the plain token sign-in), at the root and under `/abs`, since apps join the server address and the paths they get back. Its token is a Folio app token. Each edition is one item (`li_<id>`) in one of two libraries, Audiobooks and Ebooks; no socket.io, podcasts, collections or playlists.
- 2026-11-05 · Kobo sync speaks to the Kobo directly and passes nothing on to the Kobo store, so no account's data leaves Folio; store pages still open the Kobo store. Books go as EPUB (no KEPUB conversion), 100 per sync answer. The sync address's token is kept as text (to show it again) and as SHA-256 (to look it up).
- 2026-11-05 · The web app's own calls for the other apps (the addresses, the KOReader password, the Kobo address) live under `/api/apps`, so the kit's API client (always `/api`) reaches them; the protocols themselves stay at `/opds`, `/koreader`, `/kobo` and the Audiobookshelf paths.
- 2026-11-05 · A real migration run hands every waiting book to `import::queue_local` at its end; books whose files Folio can't see (the old app's folder not mounted) stay `missing` with the reason and are tried again by the next run, instead of failing verification.
- 2026-11-05 · Port, don't reimagine (the owner's call, GOALS.md): Audiobookshelf v2.37.2 (server and web), its app v0.14.2-beta and Readarr's final `develop` (2025-06-27, the project is retired) are pinned in UPSTREAM.lock; docs/PARITY.md lists 989 rows to port, and no new features land until it is done.
- 2026-11-05 · "Fork" works like Photovault: the web and mobile apps are imported as light forks (`abs-web/`, `abs-app/`) through `scripts/upstream-merge.sh`; the two backends are pinned as references only and ported to Rust, since keeping their JavaScript and C# would not be a port. Fork imports merge with a merge commit, never squashed, so the next import has a merge base.
- 2026-11-05 · Parity is proven against the original itself: endpoint tests compare Folio's answer with fixtures recorded from the pinned upstream's own image, so "works like the original" is checked field by field, not from reading code.
- 2026-11-05 · Readarr's indexers and download clients (55 rows) are `n/a`: GOALS item 2 keeps Lantern as the only way to download. Every other Readarr row, including Lantern-backed search, profiles and import lists, is ported.
- 2026-11-05 · The Audiobookshelf mobile app fork replaces the Kotlin app in `android/` once its rows are done; until then both build. Folio's Leptos pages stay only for wanted lists and Lantern, the Review queue and the ebook reader, as the owner asked.
- 2026-11-05 · Audiobookshelf's podcast features are ported too (PARITY rows P5): parity means every page and endpoint, and leaving them out would break the forked web app's pages.
- 2026-11-05 · The Audiobookshelf port keeps its data in a database of its own, `<data>/absdatabase.sqlite`, with the original's exact schema (recorded from its image, triggers and indexes included), not in `app.db`: the two `users` tables differ, and an existing Audiobookshelf database can be used as it is.
- 2026-11-05 · The recorder prints its recording into the job log (base64 of a .tar.gz) as well as uploading it, because the artifact storage host isn't reachable from every place fixtures are read.
- 2026-11-05 · Recorded answers are compared field by field, except ids (matched up so links between objects must hold), times, inode numbers and tokens, which only need the same type.
- 2026-11-05 · The Readarr port keeps its data in `<data>/readarr.db` with Readarr's exact schema (migration 158, recorded from its last image), like the Audiobookshelf port: its `Users`, `History` and `Tags` tables would collide with Folio's in `app.db` (SQLite names ignore case), its JSON shapes need its own columns, and an existing Readarr database can be used as it is. Phase 1's tables stay the library of record for files, the wanted list and Lantern.
- 2026-11-05 · Readarr's recordings come from `linuxserver/readarr:nightly-0.4.19.2811-ls400`, built 2025-06-27 from the final develop (the hotio and lscr.io images aren't reachable). Its metadata server is gone, so the test library is written straight into its database (`server/tests/parity/readarr/seed.sql`) in the formats Readarr writes, and the parity tests load the same rows into Folio, so ids and times match exactly.
- 2026-11-05 · The Readarr API answers in Readarr's shapes, errors included (ASP.NET's Not Found problem, `{message, description}`, a bare 401), not Folio's `{"detail"}`: its clients read those. The description names the .NET exception like Readarr's but has no stack trace. It accepts Folio's API key (`X-Api-Key` or `?apikey=`) or a signed-in admin.
- 2026-11-05 · The Audiobookshelf sign-in is the original's, not the kit's: its own users table, bcrypt `$2a$` hashes, HS256 tokens with the secret kept in its server settings (or `JWT_SECRET_KEY`), so an existing Audiobookshelf database signs in as before. Folio's own pages keep the kit sign-in for now; joining the two waits for P2b.
- 2026-11-05 · The phase-1 Audiobookshelf compatibility layer (`compat/abs`, answering as 2.25.1) is removed now that the port answers at the same addresses; its library and playback answers come back through the port's tracks (C and A). OPDS, KOReader and Kobo stay.
- 2026-11-05 · Express's `connect.sid` session cookie isn't set: the original only needs it for the OpenID round trip, which P2b ports. Its sign-in, refresh and sign-out cookies (`refresh_token`, `auth_method`) are set exactly like the original's.
- 2026-11-05 · Text people write is cleaned with ammonia using sanitize-html's settings from the original (same tags, attributes and link schemes); both drop everything else, so the visible result is the same.
- 2026-11-05 · Readarr caches author and book statistics, and its book editor (`PUT /api/v1/book/editor`) doesn't clear that cache, so it shows stale counts until another change. Folio always counts what is stored; the parity test lists that one difference (`DIFFERENT_ON_PURPOSE`).
- 2026-11-05 · Track C: a library page with no sort lists items in id order, and so do items that a sort ranks as equal. The original's query has no ORDER BY, so its order is whatever SQLite's planner picks and changes between recordings; Folio writes a stable order out, and the parity test compares a whole unsorted page by content.
- 2026-11-05 · Track C: the library side's parity tests load the original's own rows (`_db_end.json`, written by the recorder after the run) into Folio and replay the last, read-only requests. That way the data is the same on both sides without depending on the scanner. The order of the filter menus' authors and series comes from the original's scanner filling its cache, so that test compares them by content until the scanner port is proven.
- 2026-11-05 · The mobile fork's build changes live in `abs-app/android/app/folio.gradle`, applied by one line in `build.gradle`, and its CI is a workflow of its own (`abs-app.yml`) so upstream merges and core's `ci.yml` are untouched; the kit's `kit-android.yml` gained `web-dir`/`web-build` (kit v0.9.1) to build the Nuxt front end first.
- 2026-11-05 · The mobile fork's name, colours and icons come from a resource overlay (`abs-app/android/app/folio-res`, added to the release source set and replacing upstream's debug resources, by `folio.gradle`) instead of edits to the upstream resource files; the Encore colours map the kit's `--bg` to the app's page colour (`--color-bg`) and `--panel` to its bars and cards (`--color-primary`), the reverse of upstream's grey page, and the `audiobookshelf://oauth` redirect stays for single sign-on.
- 2026-11-05 · Track A: open playback sessions are kept in memory per data folder (the original keeps them in its session manager); its daily job that drops sessions idle for 36 hours is done whenever the list is next used, which no client can tell apart.
- 2026-11-05 · Track D: Readarr's deletes are ported with their quirks, because clients see what is left: a deleted book's files stay (its editions go first, so nothing finds them), and an author's file rows stay when its folder is deleted. Files in a Calibre library are not deleted (Readarr asks Calibre, which Folio can't reach yet): a book file there answers Readarr's "Unable to delete book file", an author's folder is kept.
- 2026-11-05 · Track D: Readarr's paths are used as they are (Folio's container mounts the library at the same paths); `READARR_DISK_ROOT` puts them under another folder, which the parity test uses for its books folder.
- 2026-11-05 · Track D: Folio writes the JSON documents in Readarr's rows compactly where Readarr indents them; both read either, so the parity test compares them by what they hold.
- 2026-11-05 · Track A: open playback sessions are kept in memory per data folder (the original keeps them in its session manager); its daily job that drops sessions idle for 36 hours is done whenever the list is next used, which no client can tell apart. Until the HLS stream is ported, a player that can't play the files directly gets them as they are.
- 2026-11-05 · Track C: the scanner lists a folder's files in name order. The original takes them in the order the file system gives (`fs.readdir`), which differs between machines and file systems; name order makes scans repeatable, and within one item the original sorts audio files by track number anyway.
- 2026-11-05 · Track C: the scanner's parity test feeds Folio the original's own ffprobe answers (`_ffprobe.json`, recorded inside the original's container), because ffprobe's durations and bit rates differ between ffmpeg versions; Folio still runs ffprobe itself everywhere else.
- 2026-11-05 · Track C: a library scan runs as a background task of its own; the original's task list (`TaskManager`, the "scanning" banner's source) comes with the server admin side, and podcast libraries are scanned once P5 ports the podcast scanner.
- 2026-11-05 · The mobile fork's pages are proven in Chromium against its web build (`abs-app/folio/e2e/`, the `web` job in `abs-app.yml`): the page code is the same on the phone, where only the storage and HTTP calls go through native plugins; native-only rows (Android Auto, the media notification, Chromecast) need their own proof.
- 2026-11-05 · Changing an API key without changing anything answers the key's owner as `{id, username, type}`, like the answer after a real change. The original sends the whole user row there, password hash included; Folio doesn't send password hashes.
- 2026-11-05 · Removing a user also removes their progress, sign-in sessions and API keys, and clears them as the maker of other keys, in Folio's code: the original's database does it by cascading foreign keys, so Folio does not depend on SQLite having foreign keys turned on.
- 2026-11-05 · Track A: the HLS stream serves pieces from the stream folder by reading them whole (6 seconds of audio each, so small) rather than adding range requests; ffmpeg runs from `APP_FFMPEG` with an argument list, and its failure reaches the listener's apps as one plain sentence ending with ffmpeg's last error line.
- 2026-11-05 · Track C: series without a sort, and series a sort finds equal, come in the order they were stored, which is how SQLite read them for the original in the recording. Authors come in id order, like library items. The original's queries have no ORDER BY for these, so the parity tests compare unsorted lists by content. A series page without `limit` is empty, like the original's, which passes a limit of 0 to its query.
- 2026-11-05 · Track D: Readarr's own metadata server (api.bookinfo.club) is gone, so when Readarr's `MetadataSource` setting is empty the port asks rreading-glasses' public server (`https://api.bookinfo.pro`), a FOSS drop-in that answers in the same format; a self-hosted rreading-glasses goes in that setting, as in Readarr. Goodreads search stays as in Readarr; `READARR_GOODREADS_URL` moves it (the parity test uses that).
- 2026-11-05 · Track D: the lookups were recorded against a stand-in metadata server and Goodreads (`server/tests/parity/readarr/stub`), because both change and Readarr's server is gone; the parity test serves Folio the same fixed answers. The stand-in's answers are made up but in the real formats, and pick cases that exercise Readarr's mapping (double spaces, redirects, editions without dates, co-written books).
- 2026-11-05 · Track D: like Readarr, the port keeps an author from the metadata server for 10 minutes and hands out its books and covers themselves, so a lookup that moves covers to Readarr's addresses changes them for the next lookup too (a book's cover can end up with its local address as `remoteUrl`). Readarr's answers show this, so the port keeps it rather than copying; the answers it keeps are held in memory where Readarr uses its cache database.
- 2026-11-05 · Track D: Readarr's lookups throw a `NullReferenceException` (503 "Invalid response received from Goodreads") for an `edition:` search whose edition the metadata server redirects to its book rather than its author, and for any one-result search on `/api/v1/search` that does so. The port answers the same, since Readarr's clients already handle that answer.
- 2026-11-05 · Schedules are checked by a port of the original's own node-cron rules (`abs/cron.rs`), quirks included (`5x` reads as `5`, a seventh field is ignored), so the apps accept and refuse the same schedules; a range longer than 10,000 values is refused instead of written out.
- 2026-11-05 · Until the mail sender is ported, sending an e-book to a device that passes every check answers like the original does when it can't reach the mail server ("Failed to verify SMTP connection configuration").
- 2026-11-05 · Notification settings are read from the database once and then kept in memory, like the original's `Database.notificationSettings`; reading them again each time would change answers (a stored `type: null` reads back as `info`).
- 2026-11-05 · Restoring a backup copies every table of the backup's database into the open database in one transaction (on a connection of its own) instead of swapping the database file like the original: Folio's database stays open the whole time. Tables the backup doesn't have are left empty; columns only one side has are skipped.
- 2026-11-05 · Backup times (ids such as `2026-11-05T1800`, `datePretty`) and the backup schedule use UTC: the image has no time zone data, and the original's image runs in UTC unless `TZ` is set.
- 2026-11-05 · A backup folder that can't be made at start is logged instead of stopping the server (the original refuses to start).
- 2026-11-06 · Library search matches text in Rust (lower case, accents removed unless the query has some, `%` and `_` as wildcards) instead of SQLite's `LIKE`: the original's image loads the nunicode extension for that, and Folio's SQLite has none. Podcast libraries search only tags and genres until podcasts are ported (P5).
- 2026-11-06 · Track D: Readarr fills in an added author's books with a command after it answers; until the command queue is ported (R5), the port runs that refresh as a background job (`readarr::refresh::Jobs`) and then applies the add options directly. Readarr applies them once its folder scan of the author ends; that scan finds nothing to change for a new author, so it is left out until the disk scan is ported.
- 2026-11-06 · Track D: the refresh is ported for new authors only; for an author or book that moved to another id at the metadata server (Readarr's merges), a book the metadata no longer lists but the library keeps, and file tags, it logs what it skips. These come with the refresh command (R5).
- 2026-11-06 · Track D: a book's rating is Readarr's `decimal` average of its editions' ratings, written with the same 28 decimals Readarr stores (`decimal_average`), so stored ratings read back to the same numbers as Readarr's.
- 2026-11-06 · Track D: Readarr's refresh stops with a `NullReferenceException` when the metadata lists a series without books (its `LinkItems` stay unset), after the author's books are written but before its series. The port stops at the same point and logs it, so the library ends up the same.
- 2026-11-06 · Mail is sent with lettre instead of nodemailer, following nodemailer's defaults (localhost, 465 or 587, STARTTLS when offered). When sending fails, the message in the answer is lettre's, worded differently from nodemailer's.
